# Verification results — Hostinger v2

Final implementation: Next.js 16.3.8, React 19.2.6, Node 22.23.3, npm 10.9.4. Test database: isolated MariaDB 10.11.14 with the MySQL protocol/driver. Original D1/source database was never used for test writes. Machine-readable evidence and timestamps: `VERIFICATION.json`.

## Passed

- Fresh npm installs and `npm ci` from the final lockfile, including an independent clean directory. The same lockfile was used in both.
- Lint: zero errors, seven existing plain-image warnings; no meaningful lint/type checks disabled. TypeScript including generated Next route types passes. Two configuration tests pass.
- Production build with no database configuration/connectivity; preview and production indexing configurations both build successfully. Standalone generated server, public assets and static chunks are present.
- Production startup on default port 3000 and non-default ports; Linux socket table confirms `0.0.0.0`. Generated-server startup used by the Hostinger preset was checked separately.
- All 12 existing public routes return 200 with expected headings/canonical URLs and structured data; unknown routes return 404. Original contact details and titles/descriptions remain. Images/favicon/static CSS resolve; all 12 sitemap entries use `https://swiftdigitals.au`.
- Preview noindex header/metadata/robots. Production robots and index/follow metadata. Production canonical Host receives no noindex header; a different temporary Host receives noindex.
- Every route fits desktop (1440×1000) and mobile (390×844) viewports. Images decode correctly; no browser page errors. Screenshots of home, NDIS and contact at both sizes were visually inspected/generated under `previews/`.
- Desktop/mobile navigation, package-to-contact service preselection through Next Link, mobile select, FAQ disclosure, skip-link keyboard focus and a full browser form submission with reference.
- Direct and Drizzle MySQL reads/writes with Unicode, apostrophes, backslashes and newlines. Genuine enquiry returns 201 after durable read-back; retry returns 200 without a second row.
- Ten concurrent requests using one UUID result in one stored record. Twelve simultaneous submissions for one email result in exactly five stored records and seven 429 responses.
- Name/email/service/message validation, JSON syntax, cross-site rejection, content type, byte limits including multibyte text, 405 for unsupported API GET, and honeypot success with no stored spam row.
- Missing database settings and unavailable database leave pages accessible and return 503 for genuine enquiries, with useful alternative contact details and no internal error/credentials exposed.
- Node migration script applies and reruns safely. Dashboard/phpMyAdmin SQL executes and reruns in an isolated database; tracker checksum mismatches are rejected; primary key and email/time index are present.
- Offline D1 conversion preserves IDs, Unicode and microsecond timestamps. Repeated MySQL imports do not duplicate records; an existing-ID data conflict is rejected before merge.
- Runtime-source search finds no active Workers/D1/SQLite/Vinext/Vite/Wrangler/auth-header imports. Database settings and SQL are absent from browser static bundles.
- Production dependency audit after patch: **zero known vulnerabilities** in the retrieved npm audit result, as of the recorded verification time.
- Original stylesheet, every public asset and original SQLite migration/journal/snapshot are byte-identical to the recorded source. Source checkout worktree remains unchanged.

## Failed

No final application checks failed. Issues found and resolved during implementation:

- The first lockfile was generated by npm 11 and failed npm 10 clean-install verification due to optional-peer AJV placement. It was regenerated in a fresh directory using the declared npm 10.9.4; final clean installs pass.
- Source Next.js 16.3.4 appeared in a critical package advisory. Although its affected `next/og` path is unused here, Next.js and matching ESLint config were patched to 16.3.8. Builds/runtime checks were rerun; the final production audit is clear.
- Existing source lint errors around internal anchors, explicit `any` and synchronous state effects were corrected with Next Link, types and a compatible form lifecycle. Visual appearance and user feedback were preserved.
